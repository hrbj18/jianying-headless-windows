# 粤仔剪辑风格

读取 [本机绑定](references/local.json) 的 `project_root` 与 `style_profile`。
先读 [规则与范例](references/rules-and-examples.md) 和 [成片精修](references/production-refinement.md)。
安装副本附带的 **v1 冻结 profile 只约束基础选段、字幕与参数证据**，不能代表完整成片风格或
审美验收。工程操作使用项目的正常 `jianying.ps1`；已有缓存可继续使用，无需重复转写参考库。

1. **素材**：先按 `<project_root>/docs/WINDOWS-MATERIAL-ANALYSIS.md` 用 `analyze` 获取真实
   转写、分章总览和候选精查。明确直播中的角色称呼，广仔与粤仔不互改。
2. **对照**：从二轮证据中选题材最接近的参考，实际看其开场、核心事件和收尾的连续或密集帧。
   写明准备复用的具体手法及时间证据；画面观察、声音检查和制作建议分别记录。
3. **干净粗剪**：读 `<project_root>/docs/WINDOWS-STORY-EDITING.md`，按真实源时间组织
   起因、推进、反转/温暖回报和结束。批量选题或主题重剪使用 `story compile` 的可选主题、
   片段贡献与停顿覆盖契约；主题由真实关系和回报支撑，每段说明删去会失去什么，动作与
   反应回查同一源事件时钟。先用原速原声和必要普通字幕审因果、接话与停顿，能看懂动作
   与答复后再加层。按动作阶段记录贡献，保留有推进的长镜头；紧凑不等于机械快切。
   结构仍弱时回到源片取舍，时长由事件决定，高光预告可选，封面独立保存。
4. **选择处理**：粗剪成立后，逐层问“删掉它，观众会少理解、看到或听到什么”。现场动作、
   脸和普通字幕已足够时保持干净；确有新增信息或必要视线引导时，比较有无关键词、反应
   图形、构图或动画的效果，再决定保留。逐处检查脸、狗与关键动作，处理密度服从题材。
   多人回应与全片焦点复审执行[精修 P11](references/production-refinement.md#p11-多人回应与全片焦点复审)。
5. **做声音**：对白原声为主体，独立安排需要声音标点的事件、对白下的音乐与闪避，并记录
   音量和落点。正常对白原速原意保留；明确标注的局部回放可另做设计与验收。字幕使用真实
   词时钟，原声不清、方言乱码和误识别歌词通过
   `subtitle_omissions` 明确记录后省略；专名修正绑定真实 ASR ID、依据与原时段，保留审计。
6. **执行**：读 `<project_root>/docs/WINDOWS-EDITING-STYLE.md`，用 `style inspect` 核验绑定的
   profile，以已审阅 selection/treatment 构建基础，再通过正常编辑、VFX、原生预览和导出入口
   完成精修。能力、资源与参数以当前文档和 catalog 为准；实际预览后再说效果已实现。
7. **对比验收**：按精修页的完成边界，对照相近参考，回查开场、全部切点、动作前后、文字
   进退、声音落点和结尾，再检查整片。写出已解决的差距与剩余差距；导出成功、轨道数和
   自评分不能替代审美证据。用户给出的目标分数是反馈目标，不转为自动认证结果。
   主题契约的粗剪、包装两阶段审稿分别绑定实际 plan/MP4 哈希，填写真正使用的检查方法；
   视觉方向负责此刻看哪里，文字设计负责何时读懂并退出，两者都围绕本条主题审收益与代价。
   需要实作范例时读[主题试剪记录](references/research/theme-trials-20261020.md)，包括删掉的处理、
   对照证据与未试听边界；不把该片的字体、时长或保留段落固化为下一片模板。
8. **交付**：读 `<project_root>/docs/WINDOWS-DELIVERIES.md`。已有四个 slot 的修订先
   `delivery inspect`，新构建通过作品和技术验收后用 `delivery promote` 替换对应位，旧版
   进入可恢复归档，首页不新增第五条。首次独立交付才使用 `publish`；内部粗剪和技术验证
   留在任务目录。提交期间保持剪映关闭，保留工程、成片、源时间/声音审计与剩余差距。

按女娲方法从本地作品建立观察、条件规则、真实范例与独立留出样本，再经新直播检验。
此 skill 沉淀可复用剪辑决策，不训练模型权重。样本、例外与验收边界见规则页和研究记录。
